Confirmed refund rules are hardcoded in `server/services/refundPolicyService.js`. The draft policy settings interface and its read/write API have been removed. Warranty duration is three calendar months, regular-product refunds default to 50% for every reason, and processing estimates are 1?3 regular / 7?14 custom calendar days. These rules cannot be edited in the admin interface. Historical database draft records are retained without an active consumer.

Regular product requests must be submitted within 14 elapsed days of recorded receipt/delivery. Customized guitar warranty requests must be submitted within three calendar months; anniversaries that fall beyond the end of a month use that month's last day, in Asia/Manila. Missing, future or disputed receipt dates require manual review. A verified date-only receipt includes the anniversary day. Eligibility is recorded at submission, so a timely request does not expire while processing. Admin verification of a disputed/missing receipt must establish eligibility using the original submission date.

Each new request stores its settings and selected-item eligibility snapshot in the existing private `review_data` JSON. Existing requests retain their original eligibility decision. No database migration is required beyond migration 50, which introduced review metadata. Regular and customized items must be submitted separately to avoid inventing allocations of verified base value and labor across different policies; the existing one-active-request-per-order rule still applies.

For every eligible regular-product refund reason, 50% is the default amount. Admins can adjust it after review; it is neither automatic approval nor a maximum. Existing eligibility snapshots and approved amounts are preserved. Admin approval remains required. Admin remarks are optional for approval and amount adjustments; a rejection reason with at least 10 meaningful characters is required when rejecting a refund. Customized monetary refunds require verified material/base value, incurred labor and supporting evidence for the selected items. The limit is `min(requested amount, verified base value, max(0, remaining actual payment - verified incurred labor))`. Actual payment includes verified payments less other reserved/completed refunds. Custom request amounts are capped at remaining actual payment when the listed item price is higher; no missing financial values or discount allocation are invented. Costs are rechecked before payment.

Processing estimates are 1–3 calendar days for regular products and 7–14 calendar days for customized guitars. The clock starts at the latest required-evidence completion and return-receipt/inspection timestamp, or documented no-return decision. Its first start is preserved and its endpoint is admin-confirmed successful payment. Estimates never automatically reject, approve or complete requests. Shipping responsibilities, reimbursement, return deadlines and repair/rework offers remain case-specific review tools.
